## 本次任务：熟悉、核查、复现，然后解释

1. 识别当前执行环境究竟是 Windows 原生还是 WSL。优先遵循文档的 WSL2 Ubuntu/Python 3.12 路线；核查 CPU、内存、NVIDIA/CUDA 可用性及依赖。使用机器已有正常权限和环境，不索要或输出凭据。先用 CPU 对齐，不随意升级版本。
2. 执行 `python -m scripts.check_environment`、`python -m scripts.check_inference`。后者应在固定 80 个合法观察上动作完全一致，概率/价值误差不超过 `1e-5`。无需 ROM。结果不一致先定位，不忽略、不修改预期值。
3. 使用明确指定的已有合法本地 ROM；参照文档执行 `scripts.install_local_rom`。不得下载不明 ROM、不得扫描/摘要识别，不提交 ROM。若本机根本没有课程匹配 ROM，可先完成无需它的工作，并明确报告缺少这个输入；不要声称已完成对局。
4. 执行 `python -m scripts.check_native`，核对 9 个 Ryu 开局及恢复重放一致性。阅读 `runtime.py`、`environment.py`、`student_actions.py` 和 `student_observation.py`，确认双方控制、P1/P2、星级、六帧输入、结束条件和部署输入的含义。
5. 使用文档列出的 `evaluate` 命令跑完整固定基线 24+8 局，不训练。不只对比总胜率，逐局比较端口、offset、对手、胜负、剩余血量、结束原因和原生帧数；与 `reports/migration_1022/focus_reference.json` 对照。若不同，先解释是否是模拟器、模型、输入序列或版本问题。
6. 根据需要录一局 CPU 八星和一局 P2 面对 strong_response，实际看录像与决策记录。区分按键请求、真实招式、位移、墙边空按和有效进退；不要以肉眼招式丰富程度或动作频率代替收益证据。
7. 阅读 PPO、FightLadder、Opponent Modeling、DRQN 的相关章节以及本地对应代码，再给出本项目流程图式解释：观察→策略/历史→42 个输入模板→双方同时推进→完整输赢→策略更新→冻结整局评估。说明当前训练了什么，没有学出什么，不把现有模拟器称成学习到的 World Model。

需要修复可复现性问题时自主做最小修复，保留前后证据。不要更换开局、对手、难度或评估口径来追上旧分数。不得运行 `notebooks/upstream` 的 Run All、原课程打包或 Arena 校验；本地独立验证不冒称官方验收。
